# Internacionalização (i18n)

O MangoStudio usa um sistema de i18n em TypeScript puro com verificação de traduções em tempo de compilação.

## Arquitetura

```
apps/shared/src/i18n/
  pt-BR.ts    → Fonte de verdade (todas as chaves definidas aqui)
  en.ts       → Traduções em inglês (tipadas contra `Messages`)
  types.ts    → Tipo `Messages` + união `Locale`

apps/frontend/src/hooks/
  use-i18n.tsx → Hook de React Context com dicionários carregados sob demanda
```

## Convenção Das Chaves

As chaves usam notação com pontos organizada por escopo de feature:

```
auth.loginTitle
chat.input.placeholder
settings.providers.caching.title
tools.generate_image.title
```

O tipo `Messages` é inferido a partir do dicionário `pt-BR.ts` usando `as const`. Adicionar uma chave em `pt-BR` sem traduzi-la em `en.ts` gera erro de compilação porque `en.ts` é tipado como `Messages`.

## Como Funciona

### Sistema De Tipos

`types.ts` define:

```typescript
type DeepStringRecord<T> = {
  [K in keyof T]: T[K] extends string
    ? string
    : T[K] extends object
      ? DeepStringRecord<T[K]>
      : never;
};

type Messages = DeepStringRecord<typeof ptBR>;
type Locale = 'pt-BR' | 'en';
```

Isso garante que `en.ts` tenha todas as mesmas chaves de `pt-BR.ts`, embora os valores possam ser strings diferentes.

### Hook React

`useI18n()` retorna `{ t, locale, setLocale }`:

```tsx
import { useI18n } from '@/hooks/use-i18n';

function MyComponent() {
  const { t } = useI18n();
  return <h1>{t.auth.loginTitle}</h1>;
}
```

- **Detecção de locale:** verifica primeiro `localStorage` (`mangostudio:locale`), depois `navigator.language`; o padrão é `en`.
- **Lazy loading:** dicionários são carregados dinamicamente conforme o locale detectado.
- **Persistência:** `setLocale()` atualiza o estado React e o `localStorage`.

### Provider

`I18nProvider` envolve a raiz da aplicação e fornece o contexto de i18n:

```tsx
<I18nProvider>
  <App />
</I18nProvider>
```

Usa a API `use()` do React 19 para consumo do contexto. Lança erro se `useI18n()` for chamado fora do provider.

## Adicionando Um Novo Idioma

1. Crie o arquivo do dicionário, por exemplo `apps/shared/src/i18n/es.ts`.
2. Copie a estrutura de chaves de `pt-BR.ts` e traduza todos os valores.
3. Tipa o arquivo como `Messages` para garantir compatibilidade estrutural:

   ```typescript
   import type { Messages } from './types';
   const es: Messages = {
     /* traduções */
   };
   export default es;
   ```

4. Adicione o locale ao tipo `Locale` em `types.ts`:

   ```typescript
   type Locale = 'pt-BR' | 'en' | 'es';
   ```

5. Adicione o locale à lógica de lazy loading em `use-i18n.tsx`.
6. Adicione a opção de locale na UI de appearance settings, se fizer sentido.

## Adicionando Novas Chaves

1. Adicione a chave em `pt-BR.ts` na seção apropriada.
2. Adicione a tradução em `en.ts` no mesmo caminho. Se você esquecer esse passo, o build falhará porque `en.ts` precisa satisfazer o tipo `Messages`.
3. Use a chave via `t.path.to.key` nos componentes.

## Seções Das Chaves

O dicionário é organizado nestas seções de topo:

- `auth` — login, signup e mensagens de erro
- `chat` — UI do chat, barra de input, feed, contexto, continuação e eventos de sistema
- `studio` — workspace de imagem
- `gallery` — página da galeria
- `settings` — tabs, contexto, prompts, general, connectors, providers, tools e appearance
- `common` — rótulos compartilhados, como salvar, cancelar, deletar e confirmar
- `providers` — nomes de exibição e descrições de provedores
- `thinking` — rótulos de thinking/reasoning
- `tools` — nomes de tools, categorias e labels de parâmetros
- `errors` — mensagens de erro
- `api` — mensagens de status da API
- `generation` — rótulos relacionados à geração
